# 外生變數歸因還原法

> 業務指標會被外生變數（天氣、節慶、政策、競品動作、系統故障）污染。把這些變數的影響量化估出來，才能看到「現場做得如何」的真實訊號。這份文件說明怎麼用固定效應迴歸正確做這件事，以及怎麼避開一堆常犯錯誤。

## 情境（什麼時候拿出來用）

- 業務想問「某外生變數對我們影響多大」（例：下雨、節假、政策退場、競品降價）
- 需要「還原」指標去跟不同時期比（跨期可比的乾淨版）
- 要給管理層「下雨週 vs 不下雨週的業績」正確對照
- 要在 BI 看板上提供「天氣校正後 traffic」

## 核心主張

- **用固定效應迴歸**（store FE + time FE），不是跑簡單均值比較
- **對照組要明確**：是「完全沒發生 vs 發生」還是「輕度 vs 重度」，意義不同
- **劑量－反應**要分段看（threshold sweep）：常不是線性
- **交互效應**（例：日類型 × 雨量）必須單獨檢查
- **污染基線**要剔除：節慶、系統停擺、資料品質問題會把對照組拉偏
- **誤差要 cluster**：同時空的觀測相關，SE 不處理會低估

## 五層分析階梯（由淺到深）

| L | 名稱 | 做什麼 | 什麼時候用 | 坑 |
|---|------|-------|-----------|-----|
| 1 | 簡單比較 | 下雨 vs 不下雨平均值 | 快速感覺數量級 | 混淆因素一堆（哪家店、哪個月、哪種日） |
| 2 | 分層比較 | 分門市／分月分別比 | 想排除某個特定混淆 | 樣本變薄、結論不穩定 |
| 3 | 分組迴歸 | 加 store dummies 分別跑 | 看是否全地區都有效應 | 每個子樣本結論不同時難整合 |
| 4 | 固定效應迴歸 | store FE + month FE + 日類型 + 控制變數 | **主結果** | 誤差結構、對照組選擇、交互效應 |
| 5 | 工具變數／DiD | 處理內生性 | 當 L4 的解釋變數本身被選擇效應污染 | 需要外生工具變數 |

**鐵則**：L1-L3 是數量感；**正式結論只信 L4+**。

## 固定效應迴歸怎麼設

### 基本模型

```
log(y_it) = β₀ + β₁·X_it + α_i + δ_t + γ_control_it + ε_it
```

- `y_it`：i 單位 t 時刻的指標（取 log 讓係數 ≈ 百分比變化）
- `X_it`：外生變數（主解釋變數）
- `α_i`：單位固定效應（吸收「這家店本來就比較多人」）
- `δ_t`：時間固定效應（吸收「這個月整體較旺」）
- `γ_control`：其他控制（例：日類型、溫度、節慶）
- SE cluster on `(高層時空單位 × 時間)`，例：城市 × 日

**用 log(y) 的好處**：係數可讀成「百分比變化」，跟商務直覺一致（「大雨 traffic 掉 17%」）。

### 控制變數該放什麼

| 類型 | 放不放 | 原因 |
|------|-------|------|
| 單位 FE | ✅ 一定要 | 吸收所有「這家店固有特性」 |
| 時間 FE（月／年） | ✅ 一定要 | 吸收季節／整體趨勢 |
| 日類型（平日／週末／國定） | ✅ 要 | 行為差別大 |
| 其他天氣（溫度） | ✅ 要 | 跟雨相關、避免偏誤 |
| 單位 × 時間趨勢 | ⚠️ 選用 | 若有「這家店趨勢上下滑」要加 |
| 競品動作、促銷檔期 | ✅ 若可觀測就要加 | 省略 = 偏誤 |

## 對照組的選擇（陷阱最多的一步）

### 坑 1：用「剩餘所有」當對照

**壞**：`heavy_rain vs 其他所有日子`（對照組混入微雨）
**好**：`heavy_rain vs rain==0`（純淨對照）

**實測**：某案的 heavy_rain 效應，用「剩餘所有」是 −13.5%，用「rain==0」是 −16.8%——**對照組選錯會低估 3pp**。

### 坑 2：對照組被節慶污染

**症狀**：含農曆年的 Holiday 子樣本，「大雨效應」出現**+24%**（反直覺）。
**原因**：農曆年期間沒有大雨日、且 traffic 本來就很低（商家休、人在外），拉低了「假日基準」。真正大雨的非農曆年假日相對這個低基準看起來偏高。
**校正**：**剔除農曆年樣本**再跑。

### 坑 3：門檻掃描（threshold sweep）要固定對照

**壞**：`rain≥T` vs `rain<T`（T 動時對照組也動）
**好**：`rain≥T` vs `rain==0`（對照組恆定）

## 劑量－反應（不要只看二元變數）

**不要**：`has_rain = 1/0`，跑一個係數。
**要**：分段看劑量－反應：

| 劑量區間 | 單位 | 效應 | 顯著性 |
|---------|-----|-----|-------|
| 0 | 基準 | — | — |
| (0, 1] | 微量 | 可能無效 | 看樣本 |
| (1, 5] | 小 | 可能顯著 | 看樣本 |
| (5, 10] | 中 | 常顯著 | — |
| (10, 25] | 大 | 大幅顯著 | — |
| (25, 50] | 極大 | 更大 | — |
| >50 | 極端 | 樣本少、不穩 | 標註 |

**作用**：
- 找「有感門檻」（例：>1mm 才有效果）
- 找「飽和點」（例：>50mm 樣本少無法估）
- 給業務「什麼程度要警覺」具體建議

---

## 交互效應（別平均掉差異）

主效應跑完後，一定要加一組**維度 × 外生變數**的交互項，看異質性。

**例**：日類型 × 雨量：

| 日類型 | 任何雨效應 | 大雨效應 |
|-------|-----------|---------|
| 平日 | −6% | −23% |
| 週末 | −8% | −21% |
| 國定（剔農曆年） | −14% | −18% |

**解讀**：
- 「平日對小雨比較沒反應」vs 「假日下雨影響最大」
- 若只跑主效應，上面差異會被平均掉

**其他常見交互軸**：
- 區域 × 外生變數
- 單位類型（旗艦／社區）× 外生變數
- 季節 × 外生變數
- 新舊客 × 外生變數

---

## 「區域沒影響」常是曝險度假象

**症狀**：主迴歸顯示「中南部不受雨影響」，北部影響大。
**實測還原**：中南部雨季是乾季，大多數雨日 < 2.4mm（小雨本就無影響）。**在同劑量下**（≥10mm），南部效應跟北部一樣大（−22% vs −17%）。

**規則**：
- 不要說「X 區域不受影響」
- 要說「X 區域曝險度低（劑量常不到門檻）」
- 給同劑量的比較才公平

## 還原公式（給下游用）

跑完迴歸拿到係數後，給下游一條**還原公式**，讓非技術人員也可用：

```python
def restore(y_actual, x_i):
    """把實際 y 還原成『x_i 不發生時的 y』"""
    if x_i >= threshold:
        return y_actual / (1 + beta_i)
    else:
        return y_actual
```

**應用**：
- BI 看板加「天氣校正後 traffic」欄
- 跨期比較時用還原值而不是原值
- 業務報告「扣除雨天因素，實際單店效能 X」

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 跑簡單平均比較就下結論 | 混淆因素一堆 | L4 固定效應迴歸 |
| 「其他全部」當對照 | 對照組混入輕度處理 | 嚴格 X==0 當對照 |
| 節慶污染基線 | 子樣本效應反直覺 | 剔除節慶再跑 |
| 二元變數替代劑量 | 看不到門檻與飽和 | 分段 bin 跑 |
| 只跑主效應 | 平均掉異質性 | 加交互效應 |
| SE 不 cluster | 顯著性誇大 | cluster on 時空單位 |
| 用原始尺度跑迴歸 | 係數不直觀 | 用 log(y) |
| 區域結論看絕對 | 曝險度差異假象 | 給同劑量比較 |
| 控制變數忘加溫度 | 跟主變數相關、偏誤 | 相關的全部放 |

## 真實案例骨架（去識別化）

### 案例 1：對照組選錯低估效應 3pp
原本「大雨 vs 其他」估 −13.5%，改「大雨 vs 完全沒雨」後估 −16.8%。差 3pp 的原因是對照組混入 1-10mm 微雨日（本身也有 −5~6% 效應）拉低對照均值。

### 案例 2：農曆年污染基線產生反直覺結果
含農曆年樣本時，「國定假日 × 大雨」效應 +24%。深挖發現農曆年期間無大雨、traffic 低、拉低了國定假日基準。剔除農曆年後正常化為 −18%。

### 案例 3：「區域不受影響」實際是曝險度差異
主迴歸顯示南部不受雨影響。改用「同劑量比較」後，南部 ≥10mm 大雨效應 −22%，跟北部 −17% 量級相當。差別在南部雨季多為小雨。

### 案例 4：門檻掃描找有感水位
用 bin 分段跑：<1mm 無效（p=0.63）、1-10mm 大約 −5-6%、>10mm −15%+。給業務的建議：「天氣 app 預報 >1mm 就該啟動 X 行動，>10mm 要調整人力」。
