# 可驗證判準框架撰寫法

> 這份文件回答的不是**某個領域**的判準怎麼寫，而是**任何判準**該長成什麼樣——判準是把「做得好不好」的直覺變成可檢核邏輯的工具，寫錯了會比沒寫更糟（給出看似客觀其實偏誤的結論）。

## 情境（什麼時候拿出來用）

- 寫報告需要給「好／壞」結論
- 做決策支援：要幫決策者過濾訊號
- 設計 KPI／評估制度：要定義什麼算達標
- 寫 skill／agent：要內嵌一組決策規則
- 把一個資深判斷力變成可轉移資產

## 核心主張

**判準 ≠ 公式**。判準是一組可檢核的規則，具備：

1. 明確回答「什麼問題」
2. 多視角拆解（禁單一視角定調）
3. 配對指標（禁單一指標誤判）
4. 不可相減規則（不同分母的比率不可相減）
5. 多定義誠實揭露（沒有單一答案時明說）
6. ⬜ 不可判定格（禁相近指標代理頂替）
7. 定調從表推導，不查表
8. 衝突另置，不污染判準
9. 每條規則對應一個實測失敗案例（E 編號）

## 判準的九條元規則

### 元規則 1：先把問題寫成一句話

**壞寫法**：「評估 X 的影響」
**好寫法**：「某方做了 Y 後，A/B/C 三個視角分別因為 Y 變成什麼樣」

**檢核**：這句話讀完，讀者能說出「要產出什麼」。產出若不能寫在一張表／一張圖，問題寫得不夠具體。

### 元規則 2：多視角，禁單一定調

**鐵則**：好壞取決於坐在哪個位子。同一組數字，從 A 位子看是成功、從 B 位子看是委屈。

**怎麼切視角**：
- **利益關係人視角**：發起方／承受方／第三方
- **時間視角**：事前／事中／事後
- **空間視角**：局部／整體
- **層次視角**：個體／群體／系統

**產出格式**：三視角變化表（**不是**單一標籤）。

```
         這次變動
            │
   ┌────────┼────────┐
視角 A    視角 B    視角 C
```

**為什麼**：標籤是壓縮，三視角資訊壓不進一個標籤裡。壓進去就是定調偏誤。

### 元規則 3：配對指標，禁單一指標

任何「相對變化」類指標都要**同時**報「成長力道」和「量體」兩個維度。

| 常見配對 | 回答什麼 |
|---------|---------|
| YoY % + pp 差 | 「漲得兇不兇」+「對大盤影響多大」 |
| 相對變化 + 絕對變化 | 力道 + 量體 |
| 比率 + 分母 | 效率 + 規模 |
| 平均 + 分布 | 中心 + 散佈 |

**只看 YoY%** → 系統性放大小基期（1% → 3% 看起來 +200%，實際對大盤 +0.2pp）
**只看 pp** → 系統性偏袒大基期（4% → 4.5% 寫成「+0.5pp」掩蓋了「只動 12.5%」）

**報告規則**：配對指標必須並列成兩欄。任何只出現一欄的比較視為未完成。

### 元規則 4：不同分母的比率，永遠不可相減

**最常見的錯誤**：拿「本店 YoY（分母=自己）」減「大盤 YoY（分母=全市場）」。

```
❌ 「本店 +15%，大盤 +36%，跑輸大盤 21pp」
   → 兩個分母不同，差額在數學上不對應任何量

✅ 「本店市占 YoY −X%」（用同一分母：全市場）
```

**延伸鐵則**：判「有沒有贏過市場／對手」一律用相對市占；絕對量只能描述自己，不能證明贏過別人。

### 元規則 5：多定義 → 多口徑並列

遇到「X 成長多少」這類問題，若 X 的「範圍／邊界」在期間內變動（版圖變了、口徑變了、人數變了），**沒有單一答案**。

**壞寫法**：挑一個數字當答案。
**好寫法**：

| 口徑 | 固定什麼 | 回答什麼 | 不能回答什麼 |
|------|---------|---------|-------------|
| A | ... | ... | ... |
| B | ... | ... | ... |
| C | ... | ... | ... |

**規則**：
- 禁止用單一成長率回答範圍可變的問題
- 必須列出至少 3 種口徑，每個標明回答什麼問題
- 「做得好不好」只用其中特定幾個口徑，明文指定

### 元規則 6：⬜ 不可判定 — 禁相近指標代理

判準所需資料不存在時 → 填 **⬜ 無法判定**。

**嚴禁**：
- 用「相近但不是」的指標頂替（例：品牌絕對量 ≠ 市占率）
- 用「過得去」的近似答案（例：用「某區域總量」代表「這家店所在的點」）
- 口頭說「大概」然後填數字

**作用**：
- 讀者知道哪些結論是硬的、哪些是空的
- 下次補資料知道該補什麼
- 任一視角 ⬜ → 不下總體定調，改講「能確定／不能講／補什麼」

### 元規則 7：定調從變化表推導，不查表

**壞做法**：寫一張 2×2×2 的查表「X=好、Y=壞、Z=好 → 整體：中性」。
**好做法**：定調**邏輯**（例：三視角全綠=全贏；某視角黃=未證明；某視角紅=有問題；任一⬜=不定調）。

**為什麼**：
- 查表會固化判斷，實際情境組合比表格豐富
- 邏輯可延伸到新情境
- 查表容易把「正常好事」判成異常（例：三方同時好完全可能，不是意外）

### 元規則 8：衝突另置，不污染判準

分析過程會發現**旁支風險**（例：同品牌虹吸、通路衝突、合規隱憂）。這些是**下一回合的事**，不是這次變動的結果。

**規則**：
- 分成「主判準」和「值得續盯」兩區
- 衝突寫進「值得續盯」，不進主判準
- 把衝突寫進主判準 → 會把一組三方都好的局，誤寫成「有問題」

**好格式**：
```
主判準：✅ 全贏
值得續盯：
- 風險 A：下一期需觀察 ...
- 風險 B：若 Y 變動則 ...
```

### 元規則 9：每條規則 → 一個實測失敗案例

**判準規則不是演繹推出的，是從失敗中學來的。**

**撰寫規則**：每條規則後面加 `[E#]`，對應附錄的一個真實錯誤：

```
鐵則 2：市占率必須 YoY% + pp 並列。[E3]

附錄 [E3]：
原始問題：三位分析師看同一組資料，只看 pp 時，一致判「兩家一樣好」，
實際一家把自己盤子做大一倍，另一家只動八分之一。
修正：加 YoY% 欄位後，分歧立刻消失。
```

**作用**：
- 讀者看到規則覺得「這不是廢話嗎」時，`[E#]` 證明這條規則是**血的教訓**
- 下次要改規則前，先看它當初解掉什麼問題
- 新進分析師知道哪些規則是「摸過才知道痛」的

## 判準框架骨架（Template）

寫新判準時，照這個骨架：

```markdown
# 判準框架：[問題一句話]

## §0 一頁邏輯骨架
- 它回答什麼：[一句話]
- 為什麼要多視角（第一鐵則）
- 三視角圖
- 每視角判準＋判定值
- 量數字的紀律（鐵則 2–N）
- 算不出來時 → ⬜
- 定調推導邏輯

## §1 骨架展開
- 適用範圍 / 不適用範圍
- 第一鐵則：[多視角]  [E1]
- 第二鐵則：[配對指標]  [E2]
- 第三鐵則：[不可相減]  [E3]
- 第四鐵則：[多口徑並列]  [E4]
- 第 N 鐵則：...
- 不可判定 (⬜) 的用法  [EN]
- 衝突另置的用法  [EN+1]

## §2 定調語

## §3 檢核清單
報告寫完前自己對一次：
- [ ] 三視角都填了嗎？
- [ ] 配對指標都並列了嗎？
- [ ] 有沒有不同分母相減？
- [ ] 可變範圍問題報了多口徑嗎？
- [ ] ⬜ 格有誠實標嗎？
- [ ] 衝突進了「值得續盯」而非主判準嗎？
- [ ] 定調推導走邏輯還是查表？

## §4 附錄：E 編號失敗案例集
[E1] ...
[E2] ...
...
```

## 判準品質檢核（給別人的判準打分用）

拿到別人的判準框架，用這 9 題檢核：

1. **問題寫成一句話**了嗎？讀者說得出要產出什麼？
2. **多視角**還是單一視角定調？
3. 相對變化指標有**配對**嗎？
4. 有沒有**不同分母相減**？
5. 範圍可變的問題有**多口徑並列**嗎？
6. 不可算有**⬜ 格**嗎？還是硬套相近指標？
7. 定調走**邏輯推導**還是查表？
8. 衝突另置還是污染判準？
9. 規則有**實測失敗案例**佐證嗎？

9 題全綠 → 這份判準是硬的。
任一題紅 → 這份判準有結構性風險。

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 「看情況」判準 | 判準寫一堆「視情況而定」沒有判定值 | 強制每條有 ✅/⚖️/❌/⬜ 選項 |
| 單視角判準 | 只看「我方」或「市場」 | 加對手／第三方視角 |
| 單指標 | 只 YoY% 或只 pp | 強制配對 |
| 代理頂替 | 「沒有 X 資料所以用 Y 近似」 | 改填 ⬜ |
| 多指標疊加成總分 | 把三視角 X 權重 = 總分 | 禁；三視角各自判，不加總 |
| 把衝突寫進主判準 | 「三方都好但 X 風險所以中性」 | 衝突另置 |
| 查表定調 | 列 2^N 種組合表 | 寫邏輯 |
