# 紅隊自我挑戰 methodology

> 寫完一份策略討論稿、分析報告、架構提案後，最危險的狀態是**自己讀自己的作品都覺得有理**。這份 methodology 派兩個獨立 subagent 做「紅隊」—— 一個負責資料 / 方法論、一個負責商業策略 —— 刻意找漏洞。結論用「致命傷 / 中度傷 / 表達型 / 要補資料」四類分級，最後產出「要收回或改口的主論點」表。

## 情境（什麼時候拿出來用）

- 寫完一份要給老闆 / 外部 review 的策略稿 / 分析報告 / 架構提案
- 自己讀都覺得有理，但「有理 ≠ 正確」
- 決策前對結論做壓力測試
- 想避免「發出去才被打」
- 跟長官討論前自己先過一輪

**跟 [[hypothesis-falsification]] 的差別**：
- 那份是「拿一條假設找資料證偽」
- 這份是「拿一整份作品找所有漏洞」+ 分級 + 結論降級

## 核心主張

**自己讀自己作品只會看到支持結論的訊息**。紅隊的工作是**刻意挑戰**：

1. **兩個獨立 subagent**，各看不同角度（資料 / 策略）
2. **只列有具體引用的挑戰**（不接受「可能有問題」）
3. **每個挑戰指向主論點哪一段**（「打誰」）
4. **挑戰分四級**（致命 / 中度 / 表達 / 要補資料）
5. **產出「要收回或改口」表**（不只發現問題，給改口文字）

**鐵則**：紅隊不是為了否定作品，是**讓作品撐得住外部挑戰**。該收回的現在收回、該降級的現在降級，比發出去被打乾淨。

## 骨架（文件章節）

### § 0. 前言：這次派了哪些紅隊

```markdown
派了兩個 subagent 對 <主稿> 做刻意挑戰：
- 紅隊審查員 資料組（資料 / 方法論面）
- 紅隊審查員 策略組（商業策略面）

以下**只列有具體引用的挑戰**，並在每點標出「主論點裡哪一條被打」。
```

**兩個 subagent 的理由**：
- 資料組：抓口徑不對、數字錯映射、檔期混常態、分子分母不同層
- 策略組：抓段位誤判、競品靜態假設、cannibalization 漏算、框架錯置
- 一個人同時當這兩個 agent 會混淆焦點

### § 1. 致命傷（會直接推翻結論的）

**鐵則**：每條挑戰四個欄位：

```markdown
### N. <一句話標題>

- **打誰**：§X 的 Y 段 / <主論點的哪一條>
- **傷在哪**：
  - 具體發現 1（附 line number / 檔案路徑）
  - 具體發現 2
  - **同口徑重算 / 反事實檢查**：<新的數字>
  - **結論反轉**：<原結論錯 / 應改成什麼>
- **收回**：<具體要收回的句子>
```

**致命傷的三種常見 pattern**：

#### 1.1 口徑不同硬比
- 兩個品牌的「現金價」一個算了補助、一個沒算
- 疊同口徑後結論反轉

#### 1.2 樣本 n=1 推結構性結論
- 「X 品牌放棄 Y 段位」只用一款 SKU 單一時點
- 可能是清庫存不是戰略

#### 1.3 檔期價當常態價
- 一份資料剛好都在檔期上
- 「直扣幅度」沒標「檔期 vs 常態」

### § 2. 中度傷（削弱結論但不推翻）

**鐵則**：標明打誰、但接受結論可能仍成立：

- 段位切法是「供給側」還是「消費者替代」？
- 競品靜態假設（沒模擬競品反應）
- cannibalization 評估層級不對（該在選項層，寫在「決定前確認」層太淺）
- 主從軸配置錯（該當主策略的放成橫向側翼）

### § 3. 表達型（結論可能對，論證方式有毛病）

**鐵則**：不打結論、只打論證：
- 數字沒說出處（median 還是別的統計？）
- 自相矛盾（前文承認某資料不能比，後文照用）
- 檔外知識塞進策略證據（沒在資料裡出現）

### § 4. 要補的資料 / 要修的程式

紅隊常順便抓到「要補 X 資料 / 修 Y 程式」：

```markdown
| 優先 | 項目 | 位置 |
|------|------|------|
| P0 | 加 all_in_after_subsidy 欄，讓不同品牌同口徑 | `scripts/build_all.py` |
| P0 | 修 REG_TO_PDF：拿掉錯映射 | `build_all.py` L1245 |
| P1 | <某項目> | <位置> |
```

### § 5. 要收回或改口的主論點（關鍵產出）

**鐵則**：紅隊不只是發現問題，給改口文字：

```markdown
| 原本結論 | 收回/改口成什麼 |
|---------|----------------|
| 「X 已穿透 Y 底部」 | **錯**。同口徑重算，<新數字>都比 X 低 |
| 「Y 被 Z 促案吃掉」 | **降級**：Y 收縮是事實，但因果連到 Z 沒時間軸證據 |
| 「W 品牌都不加碼」 | **降級**：只有 A + B 不加碼；C 沒資料（硬設 msrp） |
| 「D 單月率 27.7%」 | **標明**：單月檔期價，不是常態；「符合資格加碼 5k」門檻不透明 |
| 「E 段位競爭鬆散」 | **換讀**：也可能是旗艦客層對促案 elasticity 低 |
| 「F 是橫向問題」 | **換位置**：F 應該是主策略軸，不是側翼 |
```

**五種改口形式**：
- **錯** → 完全收回
- **降級** → 保留觀察事實，拿掉因果
- **標明** → 加限定條件（「單月」「檔期價」）
- **換讀** → 保留現象，給替代解釋
- **換位置** → 結論對但主從錯置

### § 6. 對「下一步」的影響

```markdown
原討論稿 §N 的下一步優先序**都對且該做**。

但**多加 K 件**：
1. <新優先項 1>
2. <新優先項 2>

**正式立場**：在 <資料缺口> 補完前，不對 <決策> 拍板任何 <細項>。
目前討論稿只能當「初步觀察 + 假設清單」，不是決策依據。
```

**「正式立場」stand-down 很重要**：
- 紅隊打完後，自己要做決定「現在這份能決策嗎？」
- 如果不能，**明說不能**。不要含糊「以後再議」

## 設計決策：為什麼派兩個 subagent

**單人紅隊的坑**：
- 自己的作品，自己最難刻意挑戰
- 想到的挑戰都是「作者原本已經想到的」
- 容易挑戰完變成「其實我想過了，那條沒事」

**為什麼兩個 subagent**：
- **資料組 vs 策略組**負責不同攻擊面
- 兩組的結論**有交集**的那幾條最可靠（兩組獨立都看到）
- 兩組各自跑，不互相知道對方發現什麼

**叫 subagent 的 prompt 要點**：
- 「**只列有具體引用的挑戰**，沒 line number / 檔名 / 段落引用的不要寫」
- 「**不接受『可能有問題』**」—— 挑戰要落實到具體發現
- 「**每條指向主論點哪一段**」—— 不要空泛

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 自己當紅隊 | 挑戰都是作者原本想過的 | 派獨立 subagent |
| 只派一個紅隊 | 看不到跨領域漏洞 | 資料 + 策略兩組 |
| 「可能有問題」 | 空泛無法處理 | 要具體引用 |
| 挑戰沒標「打誰」 | 不知道該改稿子哪段 | 每條指向主論點段 |
| 全部挑戰混在一起 | 不知道哪個最嚴重 | 分四級 |
| 只列問題不給改口 | 作者不知道怎麼改 | § 5 要收回/改口表 |
| 收回但保留原稿 | 讀者看到的還是舊版 | 回改原稿、紅隊結果附旁 |
| 「以後再議」 | 問題懸著 | § 6 「正式立場」要決策 |
| 沒分「降級 vs 錯」 | 要嘛全否要嘛全留 | 五種改口形式 |
| 把觀察當因果留下 | 「Y 被 Z 吃掉」 | 降級為「Y 收縮是事實，因果沒證據」 |
| 檔期價當常態寫 | 數字虛高 | 標明「檔期 vs 常態未區分」 |
| 競品當靜態樁 | 均衡分析失效 | 補「競品反應函數」 |
