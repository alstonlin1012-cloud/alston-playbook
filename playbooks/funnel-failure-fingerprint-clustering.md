# 漏斗失守指紋分群 playbook

> 想把 N 家單位（門市 / 加盟商 / 區經理 / 業務）分群對症下藥時，第一反應常是 k-means。但管理指標通常**連續分布、沒天然斷層**，silhouette 全在 0.15–0.19，硬切出來的統計群**無法命名、店長無從理解自己為何被分進去、也接不上輔導方案**。這份 playbook 改走「漏斗失守指紋」：每家店在 N 個節點上判斷是否失守，依**最上游的失守點**指派主群——互斥、可命名、對應單一處方。

## 情境（什麼時候拿出來用）

- N 家單位要分類對症下藥
- 試過 k-means 結果 silhouette < 0.3（分不出來）
- 要給非 BI 的管理層看、每群都要能命名
- 要讓單位自己能看懂「我為什麼被分到這群」
- 每群要對應**單一處方**（不是「這群可能是 A 也可能是 B」）
- 症狀相同但病因可能相反（例：都「不建 IP」但一群懶、一群挑客）

**跟 [[funnel-ranking-diagnosis]] 的差別**：
- 那份是**排序**（哪家先談，用「可追平量」）
- 這份是**分類**（這家店是哪種病，用「失守指紋」）
- 兩份互補：先排序選要看哪 N 家 → 再用這份分類 N 家各是什麼病

## 核心主張

**k-means 的坑**：
- silhouette 0.15–0.19 = 資料沒天然斷層
- 統計群**無法命名**（第 3 群 ≠ 「不建 IP 群」）
- 店長看不懂自己為何被分進去
- 接不上輔導方案（處方不是按統計特徵開的）

**漏斗失守指紋的解法**：
- 每家店在 N 個漏斗節點上判「失守 / 沒失守」
- 依**最上游的失守點**指派主群
- 主群互斥（一家店只屬一群）
- 完整指紋作為**併發症標籤**（看共存問題）
- 每群對應**一個處方**（不是建議清單）

**鐵則**：**最上游先修**。下游問題在上游沒修前治不好。

## 骨架（八步）

### Step 0 — 先試 k-means 證明不行

**鐵則**：不要跳過 k-means 直接上指紋。先試證明「資料沒天然斷層」。

跑 k = 3 到 8，每 k 取 10 組亂數種子最佳：

| k | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|
| silhouette | 0.186 | 0.155 | 0.159 | 0.168 | 0.148 | 0.151 |

全部落在 0.15–0.19 → **資料沒天然斷層**，指標是連續分佈。這個結果**寫進報告**，證明不是 BI 懶得做 k-means 而是用它不對。

### Step 1 — 定義 N 個漏斗節點

**鐵則**：節點要對應**管理動作**，不是對應資料欄位。

| 節點 | 白話在問什麼 | 失守判定門檻 | 門檻性質 |
|------|-------------|------------|---------|
| 人流 | 客人夠不夠多？ | 低於同店型中位數 75% | **相對線** |
| 建 IP | 進來的客人有沒有留資料？ | T→IP% < 1.2%（基準下限的 80%） | **及格線** |
| 跟進 | 業務有沒有在打電話？ | 聯繫 < 全公司 P25 | **相對線** |
| 轉單 | 名單有沒有變成訂單？ | IP→O% < 50%（基準下限） | **及格線** |
| 車主 | 有沒有在經營老車主？ | 車推% 或車主聯繫 < P25 | **相對線** |
| 回頭 | 有沒有追蹤沒當場買的客人？ | 回頭單佔比 < P25 | **相對線** |

### Step 2 — 分清「及格線」vs「相對線」

**鐵則**：兩種線**不要搞混**。

| 類型 | 意思 | 例 |
|------|------|-----|
| **及格線** | 公司有官方基準，低於就是**真的不及格** | 留檔 1.2% / 轉單 50% |
| **相對線** | 沒有官方基準，只能拿全公司排序來畫 | 用「後 25%」畫線 |

**相對線的陷阱**：
- 用「後 25%」= **必然會有大約四分之一的店被標記**
- 這不代表那些店真的不合格，**只代表他們相對落後**
- 母體不同答案就不同（87 家 vs 96 家會差 20%+）
- **母體選擇要固定**，寫在 code 裡並記錄原因

### Step 3 — 指派優先序（互斥的核心）

**鐵則**：節點要有**明確優先序**，依最上游的失守點指派：

```
系統未導入 → 留檔+跟進雙失 → 留檔 → 人流 → 轉單 → 車主/回頭 → 目標
```

**為什麼最上游**：
- 下游問題在上游沒修前治不好
- 建 IP 沒做時，轉單再好也是「只對高機會客人建 IP」（挑客）
- 指派最上游失守 → 單一處方夠清楚

**特殊群**：
- **G0（系統未導入）**：連資料都沒進系統，不能進一般診斷
- **目標過高**：幾乎沒失守但達成率仍差 → 這是**目標問題**，不是門市問題

### Step 4 — 分 N 群、每群命名

**群名規則**：
- 用**病症**命名（「全面停擺」「只做現場不建 IP」）
- 不用「G1/G2」（店長聽不懂）
- 包含「做了什麼」或「沒做什麼」，看就懂

**典型八群**：

| 群 | 意思 | 處方層級 |
|---|------|---------|
| **G0 系統未導入** | 連系統都沒用 | 先確認店還在不在 |
| **G1 全面停擺** | 留檔 + 跟進雙失 | P0 區經理層級 |
| **G2 只做現場不建 IP** | 有打電話但不建檔 | P1 制度層級 |
| **G3 商圈客源不足** | 人流失守 | 目標要調 |
| **G4 有 IP 不成交** | 轉單失守 | 話術訓練 |
| **G5 只吃新客不經營存量** | 車主 / 回頭失守 | 存量經營 |
| **G6 體質健康但目標過高** | 幾乎沒失守但達成率差 | 目標問題 |
| **G7 健康達標** | 無失守 | 當標竿 |

### Step 5 — 「症狀相同，病因相反」識別

**最重要的一步**：

G1「全面停擺」和 G2「只做現場不建 IP」**症狀一樣**（都是不建 IP），但：
- G1 一週打 **32 通**電話（根本沒動）
- G2 一週打 **162 通**電話（接近全公司均值）

**同樣的症狀，一個是制度問題、一個是不作為，藥不能開一樣**。

**怎麼拆**：
- 看**相鄰節點**的行為量（跟進通數）
- 看 **IP>O% 異常高**（挑客的訊號：只對高機會客建 IP）

**鐵則**：節點失守一樣，加上**鄰近節點數字**才能定病因。

### Step 6 — 併發症指紋（保留完整資訊）

每家店除了主群，還有**完整指紋**：

| 門市 | 主群 | 指紋 |
|------|------|------|
| 永和成功 | G1 全面停擺 | 留檔+跟進+轉單+車主+回頭 |
| 新竹關新 | G1 全面停擺 | 留檔+跟進+車主 |
| 中壢龍岡 | G1 全面停擺 | 留檔+跟進+車主 |

**為什麼要留指紋**：
- 主群給的是**處方優先序**（先解上游）
- 指紋給的是**完整問題**（上游解完下游要處理什麼）
- 下任看得出「這家店除了主問題還有什麼」

### Step 7 — 每群的輔導方案（量化空間）

**鐵則**：每群結尾附**可量化的回補空間**：

```
量化空間：21 家彙總 T>IP 僅 0.89%

| 情境 | 店均週 IP | 換算銷量 | 回補 |
|------|----------|---------|------|
| 現況 | 5.0 | 2,032 | — |
| 保守：T>IP → 1.2%（基準下限的 80%） | 6.8 | 2,738 | +706 台 |
| 理想：T>IP → 1.5%（基準下限） | 8.5 | 3,422 | +1,390 台 |

建議以保守情境 +706 台作為承諾值。
```

**為什麼這一步關鍵**：
- 老闆問「改善這群能回補多少」有數字可答
- 「保守 vs 理想」給承諾值的空間
- 要跟 [[funnel-ranking-diagnosis]] 的「可追平量」對得上

### Step 8 — 「可回收 vs 不可回收」總表

**鐵則**：最後一張表要說「這 N 家缺 M 台，門市端能補多少、不能補多少」：

| 群 | 店數 | 缺口 | 可回收 |
|----|-----|------|--------|
| G2 只做現場不建 IP | 16 | -885 | 423 |
| G6 體質健康但目標過高 | 14 | -583 | **0** |
| G3 商圈客源不足 | 17 | -559 | **0** |
| ... | ... | ... | ... |
| 合計 | 96 | -2,800 | 1,088（39%） |

**G6 + G3 共 31 家、缺口 41%、門市端一台也補不回來** —— 這個訊號直接讓管理層知道：
- 41% 的問題在**目標設定與商圈條件**
- 罰店長只能動 39%
- 想要全額回補 → 要動目標、動展店，不是只動現場

## 輔導方案的格式（每群一段）

```markdown
### G<N> <群名>｜<店數> 家｜<缺口> 台｜<加盟比>% 加盟

**畫像**：<六個節點的數字 + 全公司均值對照>

**診斷**：
- 「這不是能力問題，是 X 的問題」
- 具體佐證（哪幾家有什麼異常）

**輔導方案（<優先級>，<執行層級>）**
1. 第一件要做的事（往往是「先釐清 A 還是 B」）
2. 如果 A → 做 X
3. 如果 B → 做 Y
4. **量化空間**：改善到 <目標> 可回補 <N> 台

<這群所有門市的表格：門市 / 分區 / 加盟主 / 目標 / 實際 / 缺口 / 達成率 / 六節點數字>
```

**要點**：
- 「這不是能力問題，是 X 的問題」—— 給管理層框架
- **「先釐清 A 還是 B」當第一步**（別跳過 → 處方相反）
- 加盟主集中度要寫（「高度集中於某幾家加盟主」）

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| k-means silhouette 低還硬用 | 統計群無法命名 | 試過證明不行後改指紋 |
| 指派不互斥 | 一家店在多群 | 用「最上游失守」規則 |
| 群名用代號 | 店長聽不懂 | 用病症命名 |
| 症狀一樣當同一群 | 處方開錯（G1 vs G2） | 看鄰近節點行為量拆病因 |
| 只給主群不給指紋 | 下游問題被忽略 | 指紋當併發症標籤 |
| 沒分及格線 vs 相對線 | 相對線標的店被當「不合格」 | 兩種線分別註記 |
| 母體沒固定 | 相對線門檻跳動 | 母體寫進 code、記錄原因 |
| 只給診斷沒給量化空間 | 老闆問「能回補多少」答不出 | 保守 / 理想情境兩個數字 |
| 可回收寫不清楚 | 罰店長罰到目標問題店 | G6/G3 標「門市端 0」 |
| 處方優先級沒標 | 區經理不知先處理哪群 | P0/P1 + 執行層級 |
| 跳過「先釐清 A 還是 B」 | 處方開反 | 第一步必須是釐清 |

## 檢核清單（分群完成前對一次）

- [ ] 先試過 k-means 證明 silhouette 太低？
- [ ] N 個漏斗節點對應管理動作（不是資料欄位）？
- [ ] 及格線 vs 相對線分清楚？
- [ ] 相對線母體選擇固定在 code 裡？
- [ ] 指派優先序寫出來（明確到節點名）？
- [ ] 每群用病症命名（不用代號）？
- [ ] 「症狀相同但病因相反」的群有拆開（看鄰近節點）？
- [ ] 每家店有主群 + 完整指紋？
- [ ] 每群結尾附量化空間（保守 + 理想）？
- [ ] 最後有可回收 vs 不可回收總表？
- [ ] G6 / G3 類「目標 / 商圈問題」群標明「門市端 0」？
- [ ] 每群第一步輔導寫「先釐清 A 還是 B」？

## 一句話總結

> **k-means 分不出來不是資料的錯，是方法不對**。改用「最上游失守點指派主群 + 併發症指紋 + 鄰近節點拆病因 + 量化空間 + 可回收總表」—— 讓 96 家分 8 群、店長看得懂、處方對得上、老闆知道能回補多少。
