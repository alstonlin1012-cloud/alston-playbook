# 多線分析並行管理 playbook

> 同一組業務問題常拆成 3-5 條分析線（獎金彙總、紅綠燈、目標分配、區域週銷…），**共用同一批輸入**但**口徑不同**。混用會靜默算錯；每條線自己重覆建常數會前後矛盾。這份文件給一套維運這類專案的工程紀律。

## 情境（什麼時候拿出來用）

- 分析專案裡有 3+ 條線，共用輸入但輸出/口徑不同
- 每月／每期要跑新資料，交付多個 xlsx／pptx
- 一個改動（新月份／新規則）會連動 5 個地方
- 常發生「改程式沒改文件」或「文件之間互相矛盾」
- 多個 stakeholder 盯不同線，要保證交付品質一致

## 核心主張

1. **規則常數唯一來源**：每條線一個 config 檔，常數只在這
2. **連動對照表**：每個改動明文列出「改 X 必須同步改哪些」
3. **刻意獨立宣告的驗算檔**：驗算腳本獨立於產出腳本，不互相 import
4. **新資料固定流程**：先問 N 題再動手，不猜不沿用
5. **檔名由資料推導**：期別前綴自動產生，不手改

## 骨架一：三層目錄結構（每線獨立）

```
project/
├── input/                        全部唯讀原始資料
│   ├── <line_A>/                 線 A 的輸入
│   ├── <shared_data>/            共用資料
│   └── ...
├── output/                       期別前綴自動推導
│   ├── <line_A>/                 線 A 交付物
│   ├── <line_B>/                 
│   └── ...
├── scripts/                      一線一個目錄
│   ├── lib/                      跨線共用工具（上傳、認證…）
│   ├── <line_A>/
│   │   ├── <line_A>_config.py    ★ 規則常數唯一來源
│   │   ├── build_*.py            產出腳本
│   │   └── verify_*.py           驗算腳本（獨立重算）
│   └── <line_B>/
│       └── ...
├── docs/                         文件與 scripts/output 一樣分線
│   ├── <line_A>/
│   ├── 每期參數/                 每期宣告（骨架 + 各線實例）
│   └── 流程/                     維運手冊（跨檔逐步清單）
└── CLAUDE.md                     ★ 連動對照表、固定流程
```

**鐵則**：
- `input/` 唯讀
- `output/` 可重跑（有的不進版控）
- `scripts/` 每線一個目錄，**不跨線 import**（除非顯式說明例外）
- `docs/` 跟 scripts 同分區

## 骨架二：Config 檔 = 規則常數唯一來源

每條線一個 config 檔，長這樣：

```python
# <line_A>_config.py
"""
規則常數的唯一來源。新增月份 / 改規則只改這一個檔。
下游腳本只從這裡 import，不自己宣告常數。
"""

# 期別
PERIODS = ["26P1", "26P2", ..., "26P7"]
LATEST = PERIODS[-1]

# 時間映射
P_MONTH = {"26P1": "2026-01", ...}
WEEKS = {"26P1": 4, "26P2": 4, "26P3": 5, ...}  # BO 週數

# 業務規則
BONUS_CAT = {...}       # 加碼分類
BONUS_PURPOSE = {...}   # 發放目的
BAND = 0.05             # 紅綠燈帶寬
AREA_COLS = ["管理區域"]  # 區域欄名

# 逐月欄位對照（處理原檔異質性）
STORE_MAP = {
    "26P1": {"原檔欄名": "彙總欄名", ...},
    "26P2": {...},
    ...
}

# 檔名前綴（由資料推導）
PERIOD_PREFIX = LATEST  # 用於產出檔名 e.g. f"{PERIOD_PREFIX}_RS獎金彙總.xlsx"
```

**鐵則**：
- 常數**只在 config 裡**，產出腳本只 import 不重宣告
- 一線一個 config，**不跨線共用**（即便值一樣）
- 驗算腳本**刻意獨立宣告一份**（見下）

### 驗算檔要獨立宣告

```python
# verify_doc_numbers.py
"""
刻意獨立宣告一份規則常數，不從 config 讀。
用意：若 config 寫錯，驗算仍能抓出來；若互相 import，bug 會互相遮蓋。
"""

PERIODS = ["26P1", "26P2", ..., "26P7"]  # 跟 config 一樣，但獨立寫
WEEKS = {...}
# ...
```

**原因**：驗算 import 產出的常數 → 產出錯了，驗算也錯；bug 遮蓋。獨立宣告 → 兩份數字對不上 raise。

## 骨架三：連動對照表（CLAUDE.md 核心）

每個「可能改動」列一行，說明「改這個必須同步改哪些」：

```markdown
### 連動對照表

| 改了什麼 | 必須同步 |
|---------|---------|
| 加碼分類（`BONUS_CAT`） | `docs/bonus/加碼分類表.md`、重跑 `build_*.py` 產 xlsx、`README.md` |
| 紅綠燈判準、指標算法 | `docs/trafficlight/*.md`、`README.md`、重跑骨架腳本 |
| 門市對區域歸屬 | 三線統一讀 `管理區域`；改了要重跑彙總檔、店長版、區經理版、目標分配、city 週銷**五者** |
| 彙總檔分頁增刪 | `README.md` 的分頁表、讀取該分頁的下游腳本與公式 |
| 逐月欄位對照 | 跑 `verify_*.py` 確認對帳與覆蓋 |
```

**原則**：
- 每個改動至少連動 3 件事（程式／文件／驗算）
- 「程式改了文件沒改」是最常見的 bug 來源 → 對照表強制同步
- 發現既有文件之間互相矛盾 → **直接指出並修掉，不要沉默沿用**

## 骨架四：新資料固定流程（先問 N 題再動手）

新月份／新期資料進來時，有些資訊**原檔看不出來**（外部事件、政策調整、新加碼方案）。寫一個「先問再動手」清單：

```markdown
## 新增月份／新期固定流程

使用者放新月份原檔進 `input/` 時，**先問 N 題再動手**：

1. 新出現的加碼欄位歸七類的哪一類？
2. 成長率基期是否仍用 25Q4？
3. 公式骨架的 `LATEST` 是否更新到新月份？
4. 有沒有政策事件要外生調整？哪個區域、係數多少？
   （**最容易漏** — 外部資訊，三個輸入檔裡看不出來）

**答完才動手**：改 config 常數 → 補欄位對照 → 重跑 N 支腳本 → 跑 M 道驗算
```

**鐵則**：
- 不要自己猜、也不要沿用上一期的值
- 答不出來就問，不要「大概差不多」
- 第 N 題（外生事件）常被漏，寫在顯眼位置

## 骨架五：檔名由資料推導

**壞**：手動改檔名（`26P7_xxx.xlsx` → 下期要手動改成 `26P8_xxx.xlsx`）
**好**：

```python
# config 裡
PERIOD_PREFIX = LATEST  # 從 MONTHS[-1] / PERIODS[-1] 推導

# 產出腳本
output_path = f"output/<line>/{PERIOD_PREFIX}_RS獎金彙總.xlsx"
```

**作用**：
- 期別一改，所有產出檔名自動變
- 不會留下「期別已過還用舊檔名」的錯
- 不要在任何地方寫死檔名

---

## 骨架六：驗算五層紀律

多線並行最怕「某條線靜默算錯」，驗算要做五層：

| 層 | 驗什麼 | 腳本例 |
|----|-------|-------|
| 1 | 逐格重算 | `verify_*_values.py` |
| 2 | 總額歸零 | `Σ(明細) = 合計` |
| 3 | 欄位覆蓋 | 抓有沒有欄位漏分類 |
| 4 | 拆分一致 | A + B = total（跨分頁） |
| 5 | 文件數字對帳 | `verify_doc_numbers.py`（驗 md 裡 N 個關鍵數字） |

**鐵則**：
- 驗算 fail → 不交付、不 commit、找根因
- 驗算腳本**獨立寫一份常數**，不 import 產出的 config
- 新增月份要跑**全部**五層驗算，不是只跑一兩層

## 骨架七：每期參數宣告

每期產出時，產一份 `docs/每期參數/<line>/{PERIOD}_參數宣告.md`，寫清楚本期用什麼參數：

```markdown
# 26P9 門市目標分配 參數宣告

## 時間
- 本期：26P9
- 期間：2026-09-01 ~ 2026-09-28（4 週）
- 基期：26P5 ~ 26P7（13 週）

## 總目標
- 全公司 3,500 台
- OB:FR = 7:9

## 政策事件
- 高雄補助 8/11 用罄，×0.80

## 護欄
- 門市目標 ≥ 上期 × 0.7
- 業務人均上限 X 台

## 驗算
- 五道全過 ✅
```

**作用**：
- 記錄「本期用什麼參數跑的」，之後出問題能回溯
- 新接手的人看完就知道這期怎麼來的
- 用 config 的腳本自動產出（`build_period_params.py`）

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 一個常數散在 5 支腳本 | 改一處漏 4 處 | 移到 config 唯一來源 |
| 驗算 import 產出 config | bug 互相遮蓋 | 驗算刻意獨立宣告一份 |
| 跨線直接 import | 改 A 線壞 B 線 | scripts/ 按線切、不跨 import |
| 檔名寫死 | 期別過舊沒改 | 從資料推導 |
| 新月份沿用上期參數 | 錯過外部事件 | 「先問 N 題」固定流程 |
| 文件不跟著程式走 | md 與 xlsx 數字不同 | 連動對照表強制 |
| 文件間互相矛盾無人改 | 讀者困惑 | 「直接指出並修掉，不要沉默沿用」 |
| 跨期資料靜默合併 | 口徑不同算出假結論 | 每期參數宣告 md |

## 真實案例骨架（去識別化）

### 案例 1：改區域歸屬一處壞五處
原本每條線各自讀區域欄：有人讀「管理區域」，有人讀「mgmt_section」，有人直接 hard-code 對照表。某次 IT 改欄名，只有一線的開發者發現，另外四線照跑錯了一個月才被業務發現。
**校正**：統一讀 `管理區域`（config `AREA_COLS = ["管理區域"]`），改了要**明文**重跑「彙總檔／店長版／區經理版／目標分配／區域週銷 五者」。

### 案例 2：驗算 import 產出 config，bug 遮蓋
原本 verify 腳本 `from config import *`。某次 config 裡 `WEEKS` 寫錯，verify 跟著錯，產出也錯，交付給業務後兩週才被發現。
**校正**：verify 腳本改成**獨立宣告一份** `WEEKS = {...}`；兩份對不上 raise。

### 案例 3：新月份沒問外部事件
8/11 某區補助用罄。原檔第 8 月的資料正常（領牌已發生）、9 月分配目標時應該調降。分析師直接沿用上期係數（1.0），把目標砸在該區，區經理反彈。
**校正**：「新增期固定流程」第 4 題：「有沒有政策事件要外生調整？」。放顯眼位置，答完才動手。

### 案例 4：文件矛盾沉默沿用
A 文件寫「紅綠燈帶寬 5pp」，B 文件寫「帶寬 10pp」。半年後新人照 B 做，被業務打臉。
**校正**：規則「發現既有文件之間互相矛盾時，直接指出並修掉，不要沉默沿用」。
