# 份額變化歸因 playbook

> 老闆問「XX 品牌這個月份額為什麼變？」時，常見錯誤是回答「新車上市 + 舊車清庫」就結束。這份 playbook 把品牌 share 的 Δpp 拆到車款 / SKU 層，分「洞」vs「補血」，再用五種變化類型框架判斷「常態 vs 異常」「結構性 vs 短期」，產出能用在業務敘事的歸因段落。

## 情境（什麼時候拿出來用）

- 「XX 品牌 M7/M8/M9 份額為什麼變？」
- 「哪個車款搶了誰的市場？」
- 「這個月的高點／低點是常態還是異常？」
- 寫月度／季度大盤市場分析
- 要給管理層「能不能持續」的判斷（不只「發生什麼」）

**跟 [[decomposing-market-decline]] 的差別**：那份是**母體 × 行為**二層拆解（為什麼市場在縮），這份是**品牌內 SKU 層**拆解（在縮/漲的市場裡，誰得誰失）。兩份互補。

**跟 [[funnel-ranking-diagnosis]] 的差別**：那份是**跨單位排序**（哪家門市先談），這份是**單一指標時序拆解**（這個月 vs 上個月差在哪）。

## 核心主張

**share Δpp 的正確拆法是「車款層的加總 = 品牌層的 Δpp」**：

1. **分母用大盤總量，不是品牌內佔比** —— 單車款 Δpp 才能加總回品牌 Δpp
2. **「洞」vs「補血」分兩張表** —— 負貢獻看誰在流失，正貢獻看誰在補
3. **五種變化類型**（促銷尖峰 / 換代陣痛 / 新車款上市 / 家族補齊 / 既有主力回補）判可持續性
4. **「常態水位」判準** —— 扣掉異常月的單一車款貢獻後 ≈ 常態月，就講這是尖峰不是常態

## 八步骨架

### Step 0 — 確認資料截止日

**當月若未滿月**，絕對量少 20%+ 屬正常：
- 比**絕對量** → 不公平
- 比 **share %** → 仍可比

**鐵則**：任何 min/max/範圍過濾先處理 date 型別轉換。字串日期用字典序 ≠ 日期序，會踩雷。

### Step 1 — 撈月粒度品牌 share

```sql
WITH base AS (
  SELECT <ym_col> AS ym, <brand_col> AS brand, COUNT(*) AS n
  FROM <fact_table>
  WHERE <ym_col> IN (<ym1>, <ym2>, <ym3>)
    AND <quality_filter>     -- 排除法人 / 髒資料 / 無關 segment
  GROUP BY 1, 2
),
tot AS (SELECT ym, SUM(n) AS total FROM base GROUP BY 1)
SELECT b.ym, b.brand, b.n, t.total,
       ROUND(b.n / t.total * 100, 2) AS share_pct
FROM base b JOIN tot t USING(ym)
WHERE b.n >= <threshold>          -- 小量品牌濾掉避免雜訊
ORDER BY b.ym, share_pct DESC
```

**產出格式**：

| 品牌 | M7 % | M8 % | M9 % | M7→M8 Δpp | M8→M9 Δpp |
|------|------|------|------|-----------|-----------|

**口徑選擇**：
- 自然人 vs 全體：擋法人後再算
- rows vs distinct id：預設 rows；若已知有 ETL dup 用 `COUNT(DISTINCT <id>)`
- 兩個口徑都算一次做 sanity check

### Step 2 — 識別「異常月」

- **峰**：某月 share 遠高於前後月常態水位
- **谷**：某月 share 遠低於前後月常態水位
- **常態水位**：多月平均或穩定段的數字

> 異常月 → 進 Step 3 車款拆解。持平月 → 不用拆。

**為什麼這步關鍵**：如果不先篩異常月，每個月都做車款拆解會變成「報告大雜燴」。

### Step 3 — 對異常月做車款層 delta

```sql
WITH base AS (
  SELECT <ym_col> AS ym, brand, model, COUNT(*) AS n
  FROM <fact_table>
  WHERE <ym_col> IN (<ym1>, <ym2>, <ym3>)
    AND <quality_filter>
    AND brand IN ('<target_brand>')
  GROUP BY 1, 2, 3
),
tot AS (
  SELECT <ym_col> AS ym, COUNT(*) AS total
  FROM <fact_table>
  WHERE <ym_col> IN (<ym1>, <ym2>, <ym3>)
    AND <quality_filter>
  GROUP BY 1
)
SELECT b.ym, b.brand, b.model, b.n,
       ROUND(b.n / t.total * 100, 3) AS share_pct
FROM base b JOIN tot t USING(ym)
WHERE b.n >= <threshold>
ORDER BY b.brand, b.model, b.ym
```

**🚨 分母關鍵**：
- 用**整體大盤**當分母 → 單車款 Δpp 能加總 = 品牌 Δpp ✅
- 用**品牌內佔比**當分母 → 單車款 Δpp 不能加總 ❌

走錯分母 = 整份報告加總對不上，業務不信。

### Step 4 — 拆「洞」vs「補血」

對每個異常月轉折（如 M8→M9），分兩張表：

**負貢獻表（洞）**：

| 車款 | 前月 % | 當月 % | Δpp | 分類原因 |
|------|--------|--------|-----|---------|

**正貢獻表（補血）**：

| 車款 | 前月 % | 當月 % | Δpp | 分類原因 |
|------|--------|--------|-----|---------|

**驗算**：
```
淨 Δpp = Σ 正 − Σ 負
```

若加總對不上 → 剩差來自低於 threshold 的小車款雜項。寫報告時明說。

### Step 5 — 歸因框架：五種變化類型

| 類型 | 特徵 | 例 | 可持續性 |
|------|------|-----|---------|
| **促銷尖峰** | 單車款單月暴衝，隔月大幅回落 | A 車 M8 +3.48pp → M9 −3.76pp | ✗ 短期異常 |
| **換代陣痛** | 舊車款清庫 + 新車款上市同月，Δ 互抵 | B 舊 −1.43 / B 新 +1.61 | ○ 過渡期 |
| **新車款上市** | 純新品貢獻，無對應舊款清庫 | C 新 +2.28 | ✓ 結構性 |
| **家族補齊** | 系列多款同步鋪滿級距 | D 系列 150/125/125 低階同步 | ✓ 結構性 |
| **既有主力回補** | 舊車款無促銷 / 無改款，單純反彈 | E 老款 M9 +1.77 | △ 弱，易受下月節奏影響 |

**為什麼分這五類**：
- 可持續性不同 → 給管理層的建議不同
- 促銷尖峰 → 「別當常態預估」
- 新車款上市 → 「可當 base case」
- 家族補齊 → 「結構訊號，對手要小心」
- 既有主力回補 → 「觀察下月是否持續」

### Step 6 — 判斷「常態水位」vs「異常」

看多月序列，若：

```
異常月扣掉單一車款貢獻後 ≈ 常態月
```

就講：

> M8 那 XX% 只是 <車款> 促銷造的短期尖峰，M9 回到常態 YY% 才是真實水位。

**為什麼這步關鍵**：管理層問「這水位能維持嗎？」時，這套講法直接回答。

### Step 7 — 品牌敘事段落（每個品牌一段）

**格式規則**：
- 每月一段落，段間空一行
- 每月開頭：**「M<n> <狀態描述> 到 XX.XX%（±Δpp）：」**
- 冒號後換行縮排列主要車款貢獻（Δpp 標到小數兩位）
- 段末用破折號 `——` 接**一句性質判斷**（常態／尖峰／結構性／回補）

**範例**：

```
## <品牌名>

M7 常態 **XX.XX%**，<主力車款 1>（XX%）+ <主力車款 2>（XX%）撐盤；

M8 <變化描述> 到 **XX.XX%**（±Δpp）：
  <主要車款 A>（±X.XXpp）+ <主要車款 B>（±X.XXpp）<歸因短語>，
  <次要車款>（±X.XXpp）<補血/補刀>；

M9 <變化描述> 到 **XX.XX%**（±Δpp），<類型標籤>：
  **<最大 mover 車款> ±X.XXpp** + <次車款>（±X.XXpp）<歸因>，
  抵消 <反向車款>（±X.XXpp）影響，
  <品牌>淨 ±X.XXpp ——<結論性質判斷>。
```

**關鍵字字典**：新車款、上市首月、清庫、換代、促銷退潮、回補、家族補齊。

### Step 8 — 全市場 Summary（多品牌對照）

三家品牌講完後，用**一張大表 + 結構性觀察**收斂：

**大表欄位**：

| 品牌 | M7 % | M8 % | M9 % | M9 vs M8 | 增減性質 |
|------|------|------|------|----------|---------|

**「增減性質」欄寫法**：
一句話點名 2-3 個主要 mover 車款 + Δpp + 為什麼淨變 ±X.XXpp。

範例：
> 「A 車促銷退潮（−3.76pp）+ B 車清庫（−1.43pp），C/D/E 車補 +3.74pp 不足」

**必列欄位**：
- 目標品牌（市場前三）
- 代表品牌（例：某技術路線代表）
- 二線廠合併（例：SUZUKI + HONDA + PGO）
- 大盤總量列（絕對量，帶 %）

**大盤節奏行**：M7→M8、M8→M9 大盤量能變化（%），標注淡旺季 / 民俗月影響。

**結構性觀察（3-5 點）**：
1. 誰讓出份額，被誰接收？
2. 誰是真正結構性贏家（有新車款推力才算）？
3. 誰的高點需觀察（回補行情、無新車款）？
4. 誰的常態水位是多少（扣掉異常月）？
5. 大趨勢訊號（技術路線遷移 / 消費力下移 / 地域轉移）？

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 分母用品牌內佔比 | 車款 Δpp 加總對不上品牌 Δpp | 用大盤當分母 |
| 絕對量跟月份直接比 | 未滿月當減少 20% | 比 share %，標註資料截止 |
| 字串日期 min/max | 字典序 ≠ 日期序 | 先 `PARSE_DATE` |
| 每月都做車款拆解 | 報告大雜燴 | 只拆**異常月** |
| 不分「洞 vs 補血」 | 歸因亂、看不出淨方向 | 兩張表分開寫 |
| 車款名改沒對照 | 看起來新品，實際是改款 | 命名連續性註記 |
| 雜項 model 跳數字 | `model='motorcycle'` 之類 | 獨立處理 |
| ETL dup bug 當真 | 某 vin 被重複算 | 懷疑時改 `DISTINCT` |
| 法人沒擋 | 車款分佈失真 | gender / 法人 filter |
| 不講可持續性 | 老闆問「能維持嗎」答不出 | 五類型框架強制分類 |
| 不講常態水位 | 把尖峰當水位預估 | Step 6 扣掉異常車款再看 |
| 敘事不配 Δpp 數字 | 感想報告 | 每句話帶 Δpp 數字 |

## 檢核清單（寫完歸因前對一次）

- [ ] 資料截止日有標嗎？未滿月有警語嗎？
- [ ] 口徑兩個都試算（rows + DISTINCT）了嗎？
- [ ] 分母是**大盤總量**嗎（不是品牌內佔比）？
- [ ] 只對**異常月**做車款拆解（不是每個月）？
- [ ] 「洞」「補血」分兩張表嗎？
- [ ] 淨 Δpp = Σ正 − Σ負 驗算對嗎？對不上有解釋嗎？
- [ ] 每個車款變化有分類到五類型之一嗎？
- [ ] 「常態水位」vs「異常」判斷講清楚了嗎？
- [ ] 品牌敘事每句帶 Δpp 數字嗎？
- [ ] 段末有「這是 X 類型」的性質判斷嗎？
- [ ] Summary 表 + 結構性觀察 3-5 點都有嗎？
- [ ] 大盤節奏行（M7→M8、M8→M9 量能變化）有嗎？
