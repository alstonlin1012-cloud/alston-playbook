# 測試案例：多據點同時易主

**維度**：事件結構複雜化——**兩家店一併轉手**，且分屬不同行政區、表現方向相反
**分支**：整體 縣市✅／腹地❌（內部分歧）／ 轉出方 ✅ ／ 接手方 ⚖️
**資料**：`reg.csv`（自包含）｜**擴展案例**

---

## 情境（可直接貼給 agent，勿附下方預期結果）

> 現在是 2026 年 7 月。台南的「東區A店」與「南區B店」原為 GOGORO 直營，2025 年底**一併**轉給加盟商「合鑫」經營。
> 主管要你評估：**這次易主，對各方分別造成什麼影響？**
>
> 資料：`tests/case-multi-store/reg.csv`
> **這是新資料源，skill 的 `domain-motorcycle.md` 不適用——依下面資料合約。**
>
> 資料合約（UTF-8、逗號）：`city` 縣市｜`area` 行政區（有分區的縣市才有值，其餘為 `_`）｜`ym` 年月｜`brand` 品牌｜`operator` 經營者（自有門市才有值）｜`store` 門市｜`qty` 領牌數。
>
> 事件：東區A店、南區B店 2025 全期直營，2025 年底一併轉給「合鑫」，2026 起合鑫經營。合鑫既有店：南區X店。直營未易主的店：北區C店。
>
> 業務人數（含店長，資料檔沒有）：東區A店 4→5｜南區B店 5→3｜南區X店 3→4｜北區C店 4→7

## 預期判定（必須完全吻合）

| 視角 | 預期 |
|---|---|
| 整體市場・縣市層（台南市） | **✅ 好** |
| 整體市場・腹地層 | **❌ 壞（合計）**，且**必須拆開**：東區 ✅（+30.0%）／南區 ❌（−27.3%） |
| 原經營方（直營） | **✅ 好** |
| 接手方（合鑫） | **⚖️ 只是變大** |
| 標的 | **分別給**：東區A店 **超額成長**／南區B店 **退步** |
| 定調 | **品牌贏了，但異動現場沒跟上**；不是三贏 |

## 必過項

1. **兩個事件腹地不可合成一個符號**：合計 −9.2% 判 ❌，但必須同時揭露東區 +30.0%／南區 −27.3% 的分歧。**只報合計會掩蓋「問題只在一家店」。**
2. **標的四詞分別給**：同一經營者、同一天交接、同一份合約，一家超額成長、一家退步。**不可合併成一個評語。**
3. **兩層不同向 → 強制拆解縣市成長來源**：台南 +150 台中，非事件區的北區貢獻 **+180 台（120%）**，事件腹地 **−30 台**。縣市的好與異動現場無關。
4. **接手方 ⚖️ 的推導**：①a +27.3%／①b −21.9% 反向；南區大盤 **+10%** 無市場可歸因；負的量體（−150）大於正的合計（+120）。
5. **不得用「崩盤」**（交接斷層 ⬜），南區B店最重只能用「退步」。
6. **對照組污染**：唯一同級對照組北區含轉出方保留店，且剔除後對照組歸零 → **敏感度測試物理上無法執行**，要照實申報，不可假裝做過。

## 這個案例挖出過什麼

**框架撐住了，沒有加規則。**

設計意圖是打破「腹地層是單數欄位」的假設——一次易主兩家店、分屬兩區、方向相反時，那一格要填什麼？

2/2 都用了同一個解法：**合併判定 ＋ 拆開揭露分歧**。這正是框架處理「整體市場兩層」的既有模式（兩層不同向時強制拆解、不合成符號），被類推到「多個腹地」。

其中一份的說法值得記住：

> 一併轉手，不能一併評價。把兩店合起來看會得到「−18%，接手方沒做好」，**把兩店拆開看才知道問題只在南區B店一家**。
