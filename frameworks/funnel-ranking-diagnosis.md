# 業績漏斗排序診斷框架

> 管理層面對 N 家門市／區域／單位，看幾十個指標對人腦是過載的。這個框架把「一堆指標」收斂成**一個排序問題**：每個單位卡在漏斗哪一段、追平基準後可多做幾個單位、由多到少排→**最該先談的在最上面**。

## 情境（什麼時候拿出來用）

- 多單位（門市／加盟商／區經理／縣市）、每單位多指標、要給管理層一份行動清單
- 業績檢討會前，要幫 BP／RM／RS head 預先排序議題
- 設計銷售 BI dashboard 的核心排序邏輯
- 從「哪家最差」改成「先談哪家最划算」（兩者不同）

## 核心主張

**排序鑰匙不是「業績差多少」，而是「追平基準後可多做幾個單位」**。這兩者差一個系統偏誤：
- 業績差 = 絕對缺口（受單位規模／商圈／目標設定影響）
- 可追平量 = 相對基準的 gap × 單位規模（扣掉無法動的部分）

**可追平量才是「談了會變好」的機會成本正確估計**。

## 骨架（五層）

### Layer 1 — 定義主漏斗（3 階段轉換率）

**最常用形：Traffic → Intent → Order**

| 階段 | 轉換率 | 意義 | 卡住代表 |
|------|-------|------|---------|
| 1 | T→I% | 獲客力 | 人進來沒留資料 → 接待／留資話術問題 |
| 2 | I→O% | 成交力 | 名單收了成交不掉 → 跟進／逼單問題 |
| 3 | T→O% | 整體效率 | 上兩段總和（不是獨立指標） |

**I 的本質是「存量蓄水池」**：這月收的 I 是下月的成交原料，所以 I 既是本月產出，也是下月輸入。

**其他產業的 3 階段變形**：
- 餐飲：進店 → 點餐 → 回頭／加價
- SaaS：訪客 → 試用 → 付費
- 保險：接觸 → 需求確認 → 成交
- 直銷：拜訪 → 建檔 → 下單

**要點**：中段指標必須是「人／單位手動建立」的——這樣低數字可能是「沒做」也可能是「沒登錄」，兩個處理方式完全不同，分析時反覆要提。

### Layer 2 — 清洗鐵則（先洗乾淨才能比）

跑任何比較前先過這 3 條：

1. **只納入「有目標／有營運」的期間**：排除開業前、暫停、未上線的孤兒資料。累計算只加「有目標」的期間。
2. **髒資料直接標 None／空**：若中段轉換率 >130%、或分母過少（<10）→ 不估機會，不進排序。
3. **基準 = 全體加總，不是平均**：全體加總後重算一次轉換率，用這個當基準。**不要把各單位的 I→O% 平均**（會被離群值拖）。

### Layer 3 — 機會換算（排序的核心）

把「單位 vs 基準的 gap」轉成「可多做幾個單位」：

```
# 單位的基礎量
T_i = Σ 單位 i 的 Traffic（含期間所有有效月）
I_i = Σ 單位 i 的 Intent
O_i = 單位 i 的實際 Order
nmon_i = 單位 i 的營運期數

# 基準轉換率
bTI = Σ 全體 Intent / Σ 全體 Traffic
bIO = Σ 全體 Order / Σ 全體 Intent

# 單位的「追平基準」機會
# 成交機會（主，可信）
own_IO = O_i / I_i
if own_IO < bIO:
    opp_sell_i = I_i × (bIO - own_IO)
else:
    opp_sell_i = 0

# 獲客機會（參考，⚠️ 降權 0.4 不進主排序）
own_TI = I_i / T_i
if own_TI < bTI:
    opp_acq_i = T_i × (bTI - own_TI) × bIO    # 新 IP 還要再 × 成交率才會成單
else:
    opp_acq_i = 0

# 主排序鑰匙
rank_key_i = opp_sell_i                        # 由大到小
display_total_i = opp_sell_i + 0.4 × opp_acq_i  # 顯示用的「可多做」
```

**為什麼獲客機會要降權**：
- 它是「可能」還會再漏掉成交那一段的
- IP 是手動建的，低值可能是「沒登錄」而非真沒做
- 真實回收率低於計算回收率

**為什麼不排 T→O%**：
- 混合指標會把獲客問題與成交問題變成同一個數字
- 行動方案也不同（獲客問題 vs 成交問題需要不同處方）

### Layer 4 — 分群：按「誰負責解決」切

分群不是按業績高低切（高/中/低三群沒用），而是**按「這個問題誰能動」切**：

| 分群軸 | 誰能動 | 行動 |
|-------|--------|------|
| **現場執行力問題** | 門市店長／業務 | 教育訓練、建檔督促 |
| **商圈／流量問題** | 展店／區經理 | 看能否改點位、加碼廣告 |
| **目標設定問題** | BP／總部 | 修目標，不是逼現場 |
| **產品／車款問題** | 行銷／產品 | 產品配置、促銷 |
| **系統未導入** | 總部 | 補系統、補訓練 |
| **人力問題** | HR／區經理 | 招募、調度 |
| **健康達標** | 無需動 | 不動 |

**關鍵分辨點**：

| 症狀 | 可能原因 A | 可能原因 B | 分辨方式 |
|------|----------|----------|---------|
| T 多但 I 少 | 建檔沒做 | 商圈客意願低 | 看業務密度、Top sales 數 |
| I 多但 O 少 | 成交話術差 | 商品無吸引力 | 跨車款／跨檔期比 |
| T 少 | 商圈差 | 行銷不足 | 比同縣市同類型門市 |
| 全漏斗都差 | 系統未導入 / 停擺 | — | 看建檔累計 |

### Layer 5 — 「可回收 vs 不可回收」分離

**鐵則**：缺口不等於可回收，中間要扣掉**單位能動／不能動**的部分：

```
缺口 = 目標 - 實際
門市端可回收 = min(缺口, 現場執行力問題造成的部分)
不可回收 = 缺口 - 門市端可回收
```

**實測教訓**：
- 某批門市總缺口 2,800 台
- 分群後，體質健康但目標過高（14 家 −583 台）、商圈客源不足（17 家 −559 台）**合計 31 家 1,142 台（41%），門市端一台也補不回來**——問題在目標與商圈，不在店長
- 真正門市端能補回來的只有 1,088 台（39%）
- **用「總缺口排序」會把本不是門市問題的罰到店長頭上**

## 原因拆解（寫報告用）

結論段的核心排版 ≠ 「業績差多少」，而是「原因×量級×誰能解決」三欄表。按**解釋力**排序，不是按直覺排序：

| # | 原因（一句話） | 量級 | 誰能解決 |
|---|-------------|------|---------|
| 1 | [最大解釋力的原因] | [佔總缺口 X 台／%] | [單位] |
| 2 | [次大] | ... | ... |
| 3 | [第三] | ... | ... |
| 4 | [剩餘] | ... | ... |

**要點**：
- 每條原因都要有「量級」（否則變成感想）
- 「誰能解決」必須寫到可行動的具體單位（不是「大家」）
- 若 Top 1 原因不是「現場執行」，說明這份報告的價值不是「罰店長」

### 一句話總結模板

> **這不是「X」，是 Y**。
> （把直覺歸因 X 換成數據支持的 Y）

例：「這不是『賣不動』，是**目標訂得比產能快一倍，而新車的增量有四成是從自家其他車款挖來的**」。

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 用 T→O% 單一指標排序 | 把獲客問題與成交問題混成一個數字 | 分段看三轉換率，排序只用 I→O% 換算的「成交機會」 |
| 平均 vs 加總 | 把各單位的 I→O% 平均當基準 | 基準 = Σ全體分子 / Σ全體分母 |
| 髒資料硬算 | I→O% 顯示 150%（分母錯） | 直接標 None，不進排序 |
| 「業績差 = 要改善」 | 把目標過高的店拉來罵 | 分「可回收 vs 不可回收」 |
| 分群按業績高低 | 高中低三組沒行動意義 | 按「誰負責解決」切 |
| 排序鑰匙是絕對缺口 | 大店恆佔前排 | 排序用「追平基準後可多做」 |
| 把獲客機會跟成交機會相加 | 高估回收 | 成交為主，獲客降權 0.4 |
| 新車上市期直接比 | 基期不乾淨 | 標註上市週，分期分析 |
| 手動登錄當真實量 | 低值歸「沒做」 | 註明可能是「沒登錄」，看業務密度輔佐 |

## 檢核清單（報告寫完前對一次）

- [ ] 主漏斗三階段明確了嗎？
- [ ] 清洗鐵則三條都跑了嗎（有目標月、髒資料標 None、基準用加總）？
- [ ] 排序鑰匙是「可多做幾個單位」而不是「業績差多少」嗎？
- [ ] 獲客機會有降權嗎？沒進主排序嗎？
- [ ] 分群按「誰能動」切嗎？
- [ ] 「可回收 vs 不可回收」分開寫了嗎？
- [ ] 原因拆解按解釋力排序嗎？每條有量級＋負責單位嗎？
- [ ] 一句話總結是「這不是 X，是 Y」的格式嗎？
- [ ] 新車上市／檔期／外生事件標註了嗎？
- [ ] 手動登錄的指標有警語嗎？

## 真實案例骨架（去識別化）

### 案例 1：排序鑰匙改掉後，優先序整個洗牌
原排序：按「目標達成缺口」。前 10 名都是大店。
新排序：按「追平基準可多做」。前 10 名含 6 家中型店。
**為什麼**：大店缺口大一半是因為目標大。中型店雖缺口小，但轉換率離基準遠，追平的機會成本小。

### 案例 2：分群把「不能動」的店救出來
96 家門市按總缺口排序時，S3 類（體質健康但目標過高）14 家店排在前段，店長被罵。改分群後，S3 標成「門市端一台也補不回來」，問題改送 BP review 目標，店長下架。

### 案例 3：原因拆解改變行動方案
原結論：「新車 X 救不回業績，需加強推廣」。
拆解後：新車 X 的增量有 39% 從自家另一車款挖來（侵蝕），而目標拉升比產能快一倍。
**真正結論**：不是推廣問題，是目標跟產品線設計問題。
