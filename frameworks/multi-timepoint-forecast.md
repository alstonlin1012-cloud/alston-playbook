# 多時點 × 多情境預測框架

> 很多預測專案的錯誤是「用同一條公式預測整個月」。這個框架把預測沿三個軸展開：**時點** × **情境** × **層級**；每個時點對應不同的資料可得性，刻意用不同方法——強行統一反而浪費實績資訊。輸出永遠是**區間**不是點估，寬度隨時點自然收斂。

## 情境（什麼時候拿出來用）

- 要預測單一「週期」（月／季／檔期）的整體量，且**過程中會多次重預測**（例：月初、月中、月底各一次）
- 有歷史資料＋當期已實現資料兩種訊號
- 使用者（老闆／業務）會反覆問「現在這個預測準不準」
- 同週期內有不同「情境」（連假、平假日、檔期衝刺）會改變行為
- 要同時給市場總量**跟**細分層級（品牌、通路）的預測

**跟 [[forecast-three-propositions]] 的差別**：那份是**對外溝通骨架**（給老闆看什麼），這份是**實際預測邏輯骨架**（怎麼算）。兩份互補。

## 核心主張

**預測方法要隨著「已實現資料量」改變**。三個時點對應三個階段：

| 時點 | 資料可得性 | 預測方法 |
|------|----------|---------|
| 週期初（無當期資料） | 0% | 歷史同期 MoM 外推 + GAP 仲裁 |
| 週期中（W1 之後） | 20-60% | base × bump_factor（實績外推） |
| 週期末（最後 5-7 日） | 70-90% | 重算 base（排除最後一週）+ bump 觀測修正 |

強行統一公式會浪費實績資訊。

---

## 四條設計原則（被挑戰時的立場）

### A1 — 為什麼分三個時點
預測精度天生隨已實現資料量上升。三時點對應「無資料 / W1 後 / 大部分實現」三個資料可得性階段。

### A2 — 永遠輸出區間，不給單點
點預測掩蓋不確定性；業務需要 sensitivity 才能壓力測試決策。中心點 `(low+high)/2` 可作參考，但正式溝通以區間為主。

### A3 — 三時點機制刻意不對稱
月初無當期資料 → 用 MoM 仲裁；月中/月底有實績 → 用 base × bump_factor。**資料可得性決定方法**。

### A4 — 區間寬度應隨時點自然收斂
月初寬、月中中、月底窄，是正確現象不是缺陷；驗證指標應分層訂門檻。

## 骨架

### 時點 1 — 週期初（無當期資料）

**核心公式**：
```
預測區間 = 上週期實績 × (1 + r_low) × workday_factor
         ~ 上週期實績 × (1 + r_high) × workday_factor
```

**Step 1 — 三個 MoM 基準**（同質、不同時間窗）

| 基準 | 時間窗 | 意義 |
|------|--------|------|
| r_長期 | 過去 10 年 | 穩定季節性 |
| r_中期 | 過去 5 年 | 仲裁訊號（不一致時決哪邊） |
| r_近期 | 過去 2 年 | 當下動能 |

> 為什麼 10/5/2：10 年涵蓋一個產業大週期；2 年反映當前條件；5 年排除短期異常又不被太古老資料拖累。時間窗邊界本身需用歷史 MAPE 校準。

**Step 2 — 形成初步區間**
```
r_min = min(r_長期, r_近期)
r_max = max(r_長期, r_近期)
```

**Step 3 — GAP 分檔處理**（用 r_中期 仲裁）

`GAP = r_max - r_min`

| GAP | 處理 | 信心 |
|-----|------|------|
| ≤ 5% | 直接採用 `[r_min, r_max]` | 高 |
| 5% < GAP ≤ 10% | 用 r_中期 仲裁，往同側收斂 | 中 |
| > 10% | 仍按 5-10% 規則仲裁，**強制標「低信心，建議人工覆核」** | 低 |

**仲裁規則**（GAP > 5% 時）：

| r_中期 位置 | 仲裁邏輯 | 收斂後區間 |
|------------|---------|-----------|
| 靠近 r_近期 | 長期趨勢已偏移 | `[min(近, 中), max(近, 中)]` |
| 靠近 r_長期 | 近期是短暫波動 | `[min(長, 中), max(長, 中)]` |
| 落在初步區間外（罕見） | 無法仲裁 | 維持 `[r_min, r_max]`，強制低信心 |

> 為什麼用中位仲裁不用加權平均：加權平均要設「10:2 = X:Y」的主觀權重；中位仲裁不引入新參數，邏輯像「三訊號中兩個同向」業務好懂。

**Step 4 — 工作天修正**（無條件套用）
```
workday_factor = 本週期工作天 / 歷史同期平均工作天
```

比較基準是「歷史同期平均工作天」**不是**「上週期工作天」——因為 r_MoM 的平均已內含同期典型工作天。

> **鐵則**：workday_factor 獨立於 GAP 修正。工作天是「物理供給能力」，和 MoM 訊號是否一致無關。

**Step 5 — 輸出**
```
low  = 上週期實績 × (1 + r_low)  × workday_factor
high = 上週期實績 × (1 + r_high) × workday_factor
```
附信心標籤（高 / 中 / 低）。

---

### 時點 2 — 週期中（W1 結束後）

**核心公式**：
```
全週期預估 = 已實現量
           + 剩餘正常工作天 × base
           + 最後一週工作天 × (base × bump_factor)
其中 bump_factor ∈ [low_factor, high_factor]
```

- **已實現量**：直接讀數不修正
- **base**：已發生工作日的日均（依 holiday 採樣規則修正）
- **bump_factor**：月底衝刺效應，預設 `[1.15, 1.25]` 中心 1.20

**Step 1 — 計算 base（holiday 採樣修正）**

| 觸發 | 採樣調整 | 原因 |
|------|---------|------|
| 前一週 holiday = 1 天 | base 計算**剔除** holiday 結束後緊接的週一、週二 | 領取堆積導致週一二日均虛高 |
| 前一週 holiday ≥ 2 天 | 緊接整週資料 × 0.9 後納入 base 分子 | 連假後節奏被打亂，整週偏離常態 |
| 前一週無 holiday | 全週工作日直接用 | 正常 |

> **鐵則**：holiday 修正只調整 base 採樣，**已實現量本身不修正**（那是實際發生的數字）。

**Step 2 — 拆分剩餘工作天**

「最後一週」定義 = 本週期最後一個自然週（週一~週日）中落在本週期的工作日。

```
剩餘工作天 = 全週期預計工作天 - 已發生工作天
剩餘正常工作天 = 剩餘工作天 - 最後一週工作天
```

> 為什麼最後一週 = 自然週：消費者和機構都按週思考；自然週邊界清楚不需判斷；衝刺行為集中在週末前。改用「最後 5 工作日」會跨越週末邊界，行為節奏不連貫。

**Step 3 — bump_factor 區間化**

| 參數 | 預設值 | 說明 |
|------|--------|------|
| low_factor | 1.15 | 待歷史校準 |
| 中心點 | 1.20 | 業務經驗值 |
| high_factor | 1.25 | 待歷史校準 |

> 為什麼區間化而非固定 1.20：經驗值本身有月際差異，區間化能直接產出 [low, high] 比另外加修正項簡潔。

**Step 4 — 輸出**
```
low  = 已實現量 + 剩餘正常工作天 × base + 最後一週工作天 × (base × low_factor)
high = 已實現量 + 剩餘正常工作天 × base + 最後一週工作天 × (base × high_factor)
```

---

### 時點 3 — 週期末（最後 5-7 日）

**核心思路**：公式結構與時點 2 相同，差別只在：
- 已實現涵蓋更多
- 剩餘幾乎全落在最後一週
- **重算 base 時必須排除已發生的最後一週天數**

**Step 1 — 重算 base（排除最後一週）**
```
base = 非-最後一週的已實現工作日領取總和 / 非-最後一週的已發生工作天數
```

> 為什麼排除最後一週：最後一週本身有 bump，若含進 base 會把 bump 效應重複計算到「正常水準」，導致整週期預估偏高。

**Step 2 — bump_factor 觀測修正**（月底版本獨有）

至週期末，最後一週已有部分天數實現，可用觀測值修正：
```
已觀測 bump = 已發生最後一週日均 / base
```

| 已觀測 bump 位置 | 處理方式 |
|----------------|---------|
| 落在 [1.15, 1.25] 內 | 維持原預設區間 |
| > 1.25 | 區間整體上移（偏移幅度待校準） |
| < 1.15 | 區間整體下移（偏移幅度待校準） |
| 最後一週尚未開始 | 維持原預設區間 |

> 為什麼觀測修正而非直接取代：最後一週剛開始時觀測天數太少（1-3 天），純觀測外推容易過擬合單日異常；結合先驗 [1.15, 1.25] + 觀測微調比較穩。

## 情境修正（各時點自動處理機制）

**關鍵**：連假效應 = 工作天減少（物理）+ 採樣偏差（行為），分別已被不同機制涵蓋。再加 modifier 會重複計算。

| 情境 | 時點 1 | 時點 2 / 3 |
|------|--------|-----------|
| 一般 | 走標準 Step | 走標準 Step |
| 連假 1 天 | Step 4 workday_factor 自動下修 | Step 1 holiday 採樣：剔除緊接週一、二 |
| 連假 ≥ 2 天 | 同上，workday_factor 影響更大 | Step 1 holiday 採樣：緊接整週 × 0.9 |

**未涵蓋的 pattern**：連假**前**的「搶單潮」——
- 時點 1 無實績無法觀測
- 時點 2 若 W1 已含連假前幾天會被自然納入 base
- 待校準幅度是否足以影響預測精度，再決定是否加 modifier

## 驗證指標（雙層 + 分層門檻）

**雙層**：

| 指標 | 衡量什麼 | 用途 |
|------|---------|------|
| 區間命中率 | 實際是否落在 `[low, high]` | **區間化預測的主指標** |
| 中心點 MAPE | `(low+high)/2` 與實際的 MAPE | 給「需要單點」的業務溝通用 |

**分層門檻**（初稿，待校準）：

| 時點 | 目標區間命中率 | 中心點 MAPE | 信心標籤判準 |
|------|--------------|------------|------------|
| 時點 1 | ≥ 70% | ≤ 10% | GAP ≤ 5% 高 / 5-10% 中 / >10% 低 |
| 時點 2 | ≥ 80% | ≤ 7% | 例「區間寬度/中心 < 5%」高 |
| 時點 3 | ≥ 90% | ≤ 4% | 例「剩餘工作天/全週期 < 20%」高 |

> **鐵則**：用同一個 MAPE 衡量三時點是不公平的——A4 原則說區間寬度應隨時點收斂。

**待回測**：
- 門檻數字（70/80/90、10/7/4）為初始假設，需用過去 3-5 年資料 out-of-sample 校準
- 信心高/中/低三檔命中率分別應達 80% / 60% / < 50%
- 低估 vs 高估：待業務確認哪個成本較高（影響 bump_factor 是否保守偏 low）

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 一條公式跨時點 | 月底還在用 MoM 推 | 強制三時點不同方法 |
| 給點估不給區間 | 業務無法 sensitivity | A2：永遠區間 |
| 時點 3 沒重算 base | 預估偏高（bump 被算進正常） | 排除最後一週 |
| 工作天修正跟 GAP 混在一起 | 連假月份預估亂掉 | workday_factor 獨立套用 |
| 連假前後行為修正重複 | 預估過度下修 | 一個 modifier 一個 pattern |
| 比較基準用上月工作天 | 工作天修正方向錯 | 歷史同期平均工作天 |
| 加權平均 r_長/中/近 | 要調主觀權重、說不清楚 | 中位仲裁 |
| 用同一個 MAPE 衡量三時點 | 月底被要求跟月初一樣準 | 分層門檻 |
| holiday 後修正已實現量 | 修到實際發生的數字 | 只修 base 採樣 |
| 1 天用的 modifier 套 ≥ 2 天連假 | 低估節奏打亂 | 兩套判準分開 |

- [ ] workday_factor 比較基準是「歷史同期平均」嗎（不是上週期）？
- [ ] bump_factor 區間化 `[1.15, 1.25]`，中心 1.20 嗎？
- [ ] 驗證指標是雙層（區間命中率 + 中心點 MAPE）嗎？
- [ ] 分層門檻三時點分開嗎？
