# 業績診斷敘事骨架

> 分析類報告常見的痛苦版本：隨老闆逐次提問逐步長出來，4 個原因散在兩節、7 個子節混雜不同層級；讀者讀完不知道該優先動什麼。這份骨架給一個**依因果鏈重新組織**的敘事順序，讓結論可行動、可追責、可推翻。

## 情境（什麼時候拿出來用）

- 要寫業績衰退／KPI 下滑診斷報告
- 原本報告是「v1」混亂版，想重寫
- 老闆要快速知道「做什麼」
- 報告要被多個 stakeholder 審閱（BP／行銷／HR／業務）
- 要留「推翻舊結論」的痕跡

## 核心主張

**敘事順序 = 因果鏈，不是分析順序**：

```
發生什麼 → 為什麼（依解釋力排序）→ 是誰 → 做什麼 → 邊界
```

每一節回答一個「老闆會問的問題」。前一節的結論直接推下一節。

---

## 骨架五節

### 節 1 — 發生什麼（走勢 + 破口定位）

- 核心數字：目標 vs 實際、缺口、達成率
- 時序走勢：從哪週掉到哪週
- 定位第一個破口（哪一週、哪一個事件）
- **不要**解釋原因——解釋在節 2

**典型句型**：
> 「{時段}：目標 X 台，實際 Y 台，少賣 Z 台，達成率 N%。{指標} 從 W1 的 A 掉到 W4 的 B（−C%），達成率從 D 掉到 E。」

### 節 2 — 為什麼（4 個原因依解釋力排序）

**鐵則**：原因**依解釋力排序**，不是依直覺／報告產出順序。

| # | 原因（一句話） | 量級 | 誰能解決 |
|---|-------------|------|---------|
| 1 | [最大解釋力的原因] | X 台/週 or 佔總缺口 Y% | [可行動單位] |
| 2 | [次大] | | |
| 3 | | | |
| 4 | | | |

**每條原因的子節**要有：
- 證據（數字 + 圖表）
- 歸因邏輯（為什麼不是別的原因）
- 推翻紀錄（若有反覆驗證）

**一句話總結**（擺在報告最前面也擺在節 2 末）：
> 「這不是『X』，是 **Y** 」
> （把直覺歸因 X 換成數據支持的 Y）

### 節 2 附件 — 延伸問題專節

**作用**：常被問到但不是核心的問題，不混進節 2，獨立一節答。

**典型**：
| 問題 | 結論 |
|------|-----|
| 老闆常問的題 1：... | **是**（部分成立），但影響只佔 X%，不是主因 |
| 老闆常問的題 2：... | 不是變差，是沒改善 |

**規則**：每題答一句話結論 + 一行量化。避免被「這也要查那也要查」帶偏主節奏。

### 節 3 — 是誰（單位分群）

把「問題在哪」收斂成名單：

- 單位分群（例：N 家店分 K 群）
- 每群的：定義、店數、主要漏洞、可回收台數
- 每個業務分類（例：N 人分 3 類）

**分群鐵則**：按「漏斗哪一層先破」（第一失守點）分群，不按業績高低。

**作用**：節 4 的行動方案一群對一個處方。

### 節 4 — 做什麼（每個行動對應一個原因）

**鐵則**：每個行動在表格中**明標對應節 2 的哪個原因**。

| 行動 | 對應原因 | 可回收量 | Owner | 時程 |
|------|---------|---------|-------|------|
| A | 原因 1 | X 台 | Y | Q4 |
| B | 原因 2 | Z 台 | ... | ... |

**沒有對應到原因的行動** → 刪掉或移到 「backlog」。
**同一原因多個候選行動** → 排優先序。

### 節 5 — 邊界（限制 + 提問驗證紀錄 + 定義 + 重跑）

這一節常被省略，但**是分析可信度的核心**。

**子節**：
- **限制**：哪些資料沒有、哪些推論撐不住、哪些結論是部分成立
- **提問驗證紀錄**：報告寫作過程中哪些假設被推翻、怎麼驗證的、Q&A 時間順序
- **定義**：關鍵名詞（例：IP、T→IP%、新客／回頭客），放連結到字典
- **重跑**：腳本路徑、相依關係、怎麼更新資料後重跑

## 敘事鐵則

### 鐵則 1：一句話總結在最前面

**位置**：摘要段第一句或第二句。
**句型**：「這不是『X』，是 Y」。
**原因**：老闆常只讀第一段。

### 鐵則 2：量級每條都寫

原因、行動、單位群 → 每條都要有數字量級。無量級 = 感想。

**量級格式**：
- 「X 台/週」（絕對量）
- 「佔總缺口 Y%」（相對貢獻）
- 「若 X 不變，達成率會是 Z% 而非 Q%」（假設反事實）

### 鐵則 3：排序依解釋力

不要依「發現順序」「情感順序」「老闆最在意順序」排。
依**實際佔總缺口比例**排。
若最大解釋力的原因不是老闆預期的 → 這份報告就有價值。

### 鐵則 4：推翻舊結論要留痕

若某條結論被後續分析推翻 → 不要悄悄換，要明寫：

> ⚠️ 本節結論已於 vX 推翻，見 [Qn](#...)。原因：... 新結論：...

**保留舊結論的方式**：
- v1 檔不刪，保留在原位
- v2 檔頭標「相對 v1 已修正 N 項，見 §5 提問驗證紀錄」

### 鐵則 5：「每個行動對應一個原因」

節 4 的表格強制有「對應原因」欄。無對應的行動 = 離題。
同一原因的多個行動 → 並列並排序。

### 鐵則 6：關鍵名詞要有白話版

報告讀者未必是 BI。每個關鍵詞第一次出現：
- 給原名詞
- 給白話一行解釋
- 給計算公式（SQL 或口徑定義）
- 連結到完整字典

### 鐵則 7：手動登錄的指標要警語

每個「人為登錄」的指標（IP、電話次數、拜訪記錄）要警語：
> 「低值可能是『真的沒做』，也可能是『沒登錄』——這兩件事處理方式完全相反」

## 典型結構摘要表

### Part 1 走勢圖示（不要省）

```
W10 ────┐
W11     ├── 614 台/週（高峰期）
W12 ────┘
W22 ────┐
W23     ├── 515 台/週（−16%）  ← 第一破口在 W22
W25 ────┘
W26 ────── 656 台/週（新品上市反彈）
            ↑ 但達成率反而創新低（因目標也拉升）
```

### Part 2 原因四分表（必備）

| # | 原因 | 量級 | 誰能解決 |
|---|------|------|---------|

### Part 3 單位分群表（必備）

| 群 | 一句話定義 | 判定關鍵 | 店數 | 可回收 |
|----|----------|---------|------|-------|

### Part 4 行動 × 原因對應表（必備）

| 行動 | 對應原因 | 可回收量 | Owner | 時程 |
|------|---------|---------|-------|------|

### Part 5 提問驗證表（必備）

| Q# | 原始假設 | 驗證方式 | 結論 |
|----|---------|---------|------|
| Q1 | ... | ... | ✅ 成立／❌ 推翻／⚠️ 部分 |

## 常見陷阱

| 陷阱 | 症狀 | 校正 |
|------|------|------|
| 隨問題逐次長出 | 原因散在多節 | 依因果鏈重寫 |
| 依發現順序排 | 最大原因在第 3 節 | 依解釋力排序 |
| 原因沒量級 | 「我覺得」感想 | 每條有「X 台/週 or Y%」 |
| 行動沒對應原因 | 離題行動混進 | 強制「對應原因」欄 |
| 分群按業績高低 | 高中低沒行動意義 | 按漏斗第一失守點分 |
| 把延伸問題混進主節奏 | 節 2 變長 20 頁 | 單獨一節答 |
| 悄悄換結論 | 推翻舊版無痕跡 | 明寫修正紀錄 |
| 手動登錄指標當真 | 低值歸「沒做」 | 警語 + 看業務密度輔佐 |
| 沒有邊界節 | 讀者分不出硬／軟結論 | 強制節 5 |
| 關鍵詞只給技術名 | 業務讀者讀不懂 | 給白話 + 公式 + 字典連結 |

## 真實案例骨架（去識別化）

### 案例 1：v1 混亂 → v2 重組
v1 是隨老闆提問逐步長出來的，4 個原因散在兩節、7 個子節混雜門市層與業務層。讀者讀完要再問一次「所以該先做什麼」。
v2 依「發生 → 為什麼 → 是誰 → 做什麼 → 邊界」重組，4 個原因依解釋力排序，表格呈現。
**收益**：報告從 60 頁壓到 40 頁、老闆讀到第 5 頁已能決策。

### 案例 2：一句話結論倒推
原結論：「業績衰退需要加強新車推廣」。
一句話總結後：「這不是『賣不動』，是**目標訂得比產能快一倍，而新車的增量有四成是從自家其他車款挖來的**」。
**行動大改**：從「加強行銷」改成「BP 重訂目標 + 行銷改做護住自家車款不被侵蝕」。

### 案例 3：推翻舊結論留紀錄
v1 寫「W26 的 IP 正在過期」。v2 深挖後發現是「全期品質最好的一批之一」。
**做法**：v1 檔不刪；v2 檔頭標「相對 v1 已推翻 3 項結論，見 §5 Q6」；§5 寫清楚推翻理由與新資料源。
**收益**：下次有人翻 v1 不會被誤導；跨部門信任維持。

### 案例 4：延伸問題獨立節
老闆問「新人表現如何」「回頭客好不好」。這兩題跟主節奏（4 個原因）無關但常被問。
**做法**：節 2.5 單獨答，每題一個小段，給一句話結論 + 一行量化。
**結果**：主節奏不斷，又把老闆常追問題都 cover 到。
